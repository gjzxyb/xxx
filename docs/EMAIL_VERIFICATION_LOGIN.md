# 📧 邮箱验证码登录功能使用指南

## 🎯 功能概述

本系统已成功集成邮箱验证码登录功能，用户可以选择使用**密码登录**或**验证码登录**两种方式。

### ✨ 功能特性

- ✅ **双登录模式**：密码登录 + 验证码登录
- ✅ **6位数字验证码**：随机生成，安全可靠
- ✅ **5分钟有效期**：验证码有时间限制
- ✅ **60秒发送间隔**：防止恶意刷验证码
- ✅ **最多5次尝试**：超过次数需重新获取
- ✅ **精美邮件模板**：蓝色科技风格HTML邮件
- ✅ **自动清理机制**：过期验证码自动清理

## 📋 配置步骤

### 第一步：配置邮箱服务

编辑项目根目录的 `.env` 文件，添加以下配置：

```env
# 邮箱验证码登录配置
EMAIL_HOST=smtp.qq.com
EMAIL_PORT=587
EMAIL_SECURE=false
EMAIL_USER=your-email@qq.com
EMAIL_PASSWORD=your-smtp-authorization-code
```

#### 常见邮箱服务商配置

**QQ邮箱（推荐）**
```env
EMAIL_HOST=smtp.qq.com
EMAIL_PORT=587
EMAIL_SECURE=false
EMAIL_USER=your-qq-email@qq.com
EMAIL_PASSWORD=smtp-authorization-code
```

**163邮箱**
```env
EMAIL_HOST=smtp.163.com
EMAIL_PORT=465
EMAIL_SECURE=true
EMAIL_USER=your-163-email@163.com
EMAIL_PASSWORD=smtp-authorization-code
```

**Gmail**
```env
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_SECURE=false
EMAIL_USER=your-gmail@gmail.com
EMAIL_PASSWORD=app-specific-password
```

### 第二步：获取SMTP授权码

#### QQ邮箱获取授权码步骤：

1. 登录 QQ 邮箱 (https://mail.qq.com)
2. 点击顶部 **设置** → **账户**
3. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务**
4. 开启 **IMAP/SMTP服务** 或 **POP3/SMTP服务**
5. 按照提示发送短信验证
6. 获取**授权码**（16位字符）
7. 将授权码填入 `EMAIL_PASSWORD`

#### 163邮箱获取授权码步骤：

1. 登录 163 邮箱 (https://mail.163.com)
2. 点击 **设置** → **POP3/SMTP/IMAP**
3. 开启 **IMAP/SMTP服务**
4. 点击 **客户端授权密码** → **新增授权密码**
5. 获取授权码
6. 将授权码填入 `EMAIL_PASSWORD`

⚠️ **重要提示**：
- `EMAIL_PASSWORD` 填写的是**SMTP授权码**，不是邮箱登录密码
- 授权码通常是16位字符，不包含空格

### 第三步：确保用户表有email字段

验证码登录需要用户绑定邮箱。确保数据库用户表包含 `email` 字段。

如果需要为现有用户添加邮箱，可以：
1. 通过管理后台批量导入
2. 让用户在个人设置中绑定邮箱

## 🚀 启动服务

配置完成后，重启服务器：

```bash
# 停止现有服务
# 按 Ctrl+C

# 启动服务
npm start
```

启动时会看到以下日志：

```
✓ 邮件服务初始化成功
```

如果看到警告：
```
⚠️ 邮箱服务未配置，验证码登录功能将不可用
```

说明邮箱配置有误，请检查 `.env` 文件中的配置。

## 🎮 使用方法

### 用户端使用

1. 打开登录页面
2. 点击 **验证码登录** 标签
3. 输入绑定的邮箱地址
4. 点击 **获取验证码** 按钮
5. 查收邮件（通常1-5秒内到达）
6. 输入6位验证码
7. 点击 **登录** 按钮

## 🔧 API接口文档

### 1. 发送验证码

**接口地址**：`POST /api/auth/send-verification-code`

**请求参数**：
```json
{
  "email": "user@example.com",
  "projectId": "project-id"
}
```

**成功响应**：
```json
{
  "code": 200,
  "message": "验证码已发送到您的邮箱",
  "data": {
    "message": "验证码已发送到您的邮箱",
    "expiryMinutes": 5
  }
}
```

**错误响应**：
```json
{
  "code": 429,
  "message": "请等待 45 秒后再试",
  "remainingSeconds": 45
}
```

### 2. 验证码登录

**接口地址**：`POST /api/auth/login-with-code`

**请求参数**：
```json
{
  "email": "user@example.com",
  "code": "123456",
  "projectId": "project-id"
}
```

**成功响应**：
```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "jwt-token-string",
    "user": {
      "id": 1,
      "name": "张三",
      "email": "user@example.com",
      "role": "student"
    }
  }
}
```

**错误响应**：
```json
{
  "code": 400,
  "message": "验证码错误，还剩 3 次尝试机会",
  "remainingAttempts": 3
}
```

## 🛡️ 安全机制

### 防刷机制

1. **发送间隔限制**：同一邮箱60秒内只能发送一次验证码
2. **尝试次数限制**：验证码最多可尝试5次，超过需重新获取
3. **有效期限制**：验证码5分钟后自动失效
4. **自动清理**：系统每分钟自动清理过期验证码

### 错误提示

- `请等待 X 秒后再试` - 发送过于频繁
- `验证码不存在或已过期，请重新获取` - 验证码失效
- `验证码错误，还剩 X 次尝试机会` - 验证码输入错误
- `验证码尝试次数过多，请重新获取` - 超过尝试次数
- `该邮箱未绑定账号` - 邮箱未注册

## 🐛 故障排查

### 问题1：邮件发送失败

**症状**：点击"获取验证码"后提示"发送失败"

**解决方案**：
1. 检查 `.env` 文件中的邮箱配置是否正确
2. 确认 `EMAIL_PASSWORD` 是授权码，不是登录密码
3. 检查邮箱服务商的SMTP服务是否已开启
4. 查看服务器日志获取详细错误信息

### 问题2：收不到邮件

**症状**：验证码发送成功，但收不到邮件

**解决方案**：
1. 检查垃圾邮件/广告邮件文件夹
2. 确认邮箱地址输入正确
3. 等待1-2分钟（某些邮箱服务器可能延迟）
4. 尝试使用其他邮箱测试

### 问题3：验证码登录功能不可用

**症状**：登录页面没有"验证码登录"选项

**解决方案**：
1. 清除浏览器缓存（Ctrl+F5 强制刷新）
2. 检查 `client/index.html` 是否已更新
3. 确认服务器已重启

### 问题4：提示"邮件服务暂不可用"

**症状**：点击获取验证码时提示服务不可用

**解决方案**：
1. 检查 `.env` 文件中是否配置了 `EMAIL_USER` 和 `EMAIL_PASSWORD`
2. 重启服务器以重新初始化邮件服务
3. 查看服务器启动日志，确认邮件服务初始化成功

## 🔒 生产环境注意事项

### 安全配置

1. **使用专用邮箱**：建议使用独立的邮箱账号用于发送系统邮件
2. **定期更换授权码**：每3-6个月更换一次SMTP授权码
3. **监控异常**：关注异常发送量，防止被滥用
4. **备用邮箱**：配置备用邮箱服务，提高可用性

### 性能优化

1. **邮件队列**：高并发场景建议使用消息队列（如Redis）
2. **连接池**：nodemailer 支持连接池，已默认配置
3. **异步发送**：邮件发送已使用异步方式，不阻塞主线程
